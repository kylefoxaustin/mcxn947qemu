# known-deviations.txt -- registers whose reset value DISAGREES with the RM.
#
# ⛔ EVERY LINE MUST CARRY A BUCKET AND A REASON.  The gate REFUSES this file otherwise.
#
# It did not always.  For 194 lines the "reason" column held `model=0x0 RM=0xc0000000`
# -- which is THE DIFF, not a justification.  It records THAT the model disagrees with
# the manual, which is the very thing being excused, and calls that an explanation.
#
#     ⭐ AN ALLOWLIST WITHOUT REASONS IS NOT A TO-DO LIST AND NOT A CERTIFICATE.
#        IT IS A LIST OF BUGS, SORTED ALPHABETICALLY.
#
# USBPHY CTRL was in here.  The PHY powers up HELD IN SOFT-RESET AND CLOCK-GATED
# (0xC000_0000) and my model told every guest it was already released and running --
# a live, guest-visible lie -- and it sat here INDISTINGUISHABLE from 193 acceptable
# ones, because there was no field in which its wrongness could differ from theirs.
#
# 91emulator's fix is "a human types the entry, with a reason."  That alone would not
# have saved me: I WAS the human.  The REASON is the load-bearing half -- it is the
# only thing separating "I decided this is fine, and here is why" from "I got tired
# of looking at this."
#
# BUCKETS
#   DECISION:   deliberate and defended.  Say WHY the RM value is not what we model.
#               (e.g. under-reporting a capability so the guest takes a path we model)
#   UNMODELLED: the block has no model in hw/.  A GAP, not a lie.  Derivable, not judged.
#   UNTRIAGED:  NOT YET LOOKED AT, in a block we DO model.  ⚠ EVERY ONE OF THESE COULD BE
#               THE NEXT USBPHY CTRL.  THIS COUNT MUST GO DOWN.  It is not a status; it
#               is an admission.
#
# The gate also fails when an allowlisted register starts MATCHING ("delete the line") --
# the ratchet only turns one way.

#==========================================================================
# DECISION (1) -- deliberate, defended, and the reason is the point.
#==========================================================================
USDHC0         HOST_CTRL_CAP        # DECISION: we clear SDR50|SDR104|DDR50|USE_TUNING_SDR50 because THERE IS NO TUNING ENGINE IN THIS MODEL (no CMD19, no sampling window; TUNING_CTRL is storage). The RM value advertises UHS-I modes the guest would then try to USE. On a capability register, matching the RM IS the bug unless you implement the chip behind it -- 91emulator set this same register to the RM value and QEMU's own sdhci_check_capareg() REFUSED TO BOOT. We have no such assertion to catch us. Under-report: safe. Over-report: a promise the emulator makes on the silicon's behalf. These bits come back WITH the tuning engine, not before.

# DECISION -- computed STATUS registers: they follow the hardware, so they
# cannot also sit at a static reset value.  See USBHS PORTSC1[PSPD].
#==========================================================================
SAI0           TCSR                 # DECISION: the RM's reset is 0, but TCSR's FIFO request/warning flags are COMPUTED FROM REAL FIFO OCCUPANCY, not stored -- an empty TX FIFO legitimately asserts them. A CONFIG register's reset value is a FACT; a STATUS register's is a DESCRIPTION OF A STATE, and a computed status register cannot also sit at a static reset value without lying about the state it is in. Returning 0 would mean 'the FIFO does not want data', which is false of an empty FIFO. Same reasoning as USBHS PORTSC1[PSPD].
SAI1           TCSR                 # DECISION: see SAI0 TCSR -- flags computed from real FIFO occupancy, not stored.
VREF0          CSR                  # DECISION: the RM's reset is 0, but CSR's ready bits are COMPUTED from the regulator state rather than stored. Same class as SAI TCSR: a status register that FOLLOWS the hardware cannot also sit at a static reset value.
OSTIMER0       MATCH_H              # DECISION: MATCH_H holds bits 41:32 of a 42-bit gray-coded match -- TEN valid bits. We return those ten. The RM's reset value (0xFFFFFFFF) also has the RESERVED bits 31:10 reading as 1, and we do NOT fabricate reserved-bit read-back we cannot verify: the manual does not say whether they are hardwired to 1 or merely reset to 1, and inventing the answer is the exact class this gate exists to catch. The ten modelled bits ARE correct (0x3FF = all-ones = "no match scheduled", matching the RM's intent). A driver masks reserved bits. Revisit if a real driver is found to read them.
